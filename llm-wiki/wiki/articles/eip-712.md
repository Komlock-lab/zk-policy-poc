# EIP-712 Typed Structured Data

## TL;DR

EIP-712はDomainと型付きmessageを結合して、利用者が意味を確認しやすい署名形式を定義する。一方で署名の再利用防止は仕様範囲外なので、認可に使うアプリケーションがnonceやidempotencyを設計する。

## Key claims

- Domain Separatorは署名をprotocol、version、chain、contractなどへ結び付ける。
- messageは宣言したstruct typeとfield順序に従ってhashされる。
- EIP-712署名が正しいことと、その署名が未使用であることは別問題である。

## Technical details

- Domainは必要に応じて`name`、`version`、`chainId`、`verifyingContract`を使用する。
- 署名digestはEIP-191のprefix、Domain Separator、messageの`hashStruct`を結合して生成する。
- Policy更新messageへAccount、Commitment、nonce、deadlineを含めることで、対象と有効条件を明示できる。

## Limitations and caveats

- 標準はreplay protectionを含まない。
- Domain fieldを含めるだけでは、application-level nonceの消費や期限検証を代替できない。
- messageを受け取った後のfront-running耐性とidempotencyもアプリケーション責務である。

## Project relevance

- Phase 2のOwner署名付きPolicy更新APIの形式を定める。
- [[eip-712-policy-update-authorization]]でAccount単位nonceとdeadlineを必須にする根拠になる。
